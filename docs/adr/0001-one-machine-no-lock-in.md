# 0001. Одна машина без привязки к ней

- Статус: принято
- Дата: 2026-09-20

## Контекст

Проект работает на одной машине с NVIDIA GPU. При этом он должен показывать, что архитектура
переносится на кластер из нескольких узлов и на любой Kubernetes, а не только на тот, где её писали.
Разворачивать настоящий многоузловой кластер ради этого не хочется: для пет-проекта это лишние
железо и время.

## Решение

На машине работает одноузловой k3s. Это полностью совместимый дистрибутив Kubernetes: API и
манифесты те же, а containerd, сеть, DNS, local-path для томов и рантайм NVIDIA идут в комплекте.

Код и манифесты не знают, сколько узлов в кластере. Серверы моделей садятся на узлы с меткой
`gpu=true` и запрашивают ресурс `nvidia.com/gpu`, а планировщик держит столько серверов,
сколько GPU в кластере.

В CI e2e-тест гоняется на двух кластерах по три узла: k3d — тот же k3s в Docker — и kind,
ванильный Kubernetes на kubeadm. Одному узлу вешается метка `gpu=true`, вместо GPU работает
фейковая модель.

## Последствия

- Переносимость проверяется на каждом PR, а не обещается в README. e2e появится на этапе 3.
- На машине меньше инфраструктурной работы, чем с kubeadm.
- Настоящего многоузлового кластера в проекте нет, и это осознанно: потенциал показан, но не развёрнут.

## Отвергнутые варианты

- **kubeadm на машине.** API тот же, но CNI, провижнер томов, снятие taint с control-plane и
  GPU Operator ставятся руками. Для прикладного проекта это время уходит в DevOps.
- **minikube.** Удобен для одной машины, но это инструмент локальной разработки: на несколько
  реальных машин он не растягивается.
