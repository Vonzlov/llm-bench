# 0002. Откуда узел берёт образы

- Статус: принято
- Дата: 2026-09-23

## Контекст

Машина проекта находится в России, и при установке k3s выяснились три вещи. Docker Hub отдаёт
описания образов, но скачивание слоёв с его CDN (`production.cloudfront.docker.com`) обрывается
с `connection reset by peer`. Из-за этого не запустились даже системные поды k3s: их образы
тоже лежат на Docker Hub. Реестр NVIDIA `nvcr.io` отвечает `403 Forbidden`, а образ NVIDIA
device plugin публикуется только там; на Docker Hub его версии не обновляются с `v0.5.0`.

VPN проблему не решает: на Windows 10 с включённым VPN в WSL пропадает сеть, а режимы сети
WSL, которые умеют с ним уживаться, есть только в Windows 11.

При этом манифесты проекта должны оставаться переносимыми: на машине без этих ограничений
они обязаны работать как есть.

## Решение

Откуда качать образы, решает узел, а не манифесты. В манифестах остаются обычные адреса
(`ubuntu:24.04`, `nvcr.io/...`), а подмена настраивается в k3s.

- Системные образы k3s ставятся из архива air-gap того же релиза с GitHub. Порядок — в
  [инструкции по k3s](../setup-k3s-gpu.md).
- Образы Docker Hub идут через `mirror.gcr.io` — публичный кеш Docker Hub от Google
  ([`deploy/node/registries.yaml`](../../deploy/node/registries.yaml)). Проверено: `busybox:1.36`,
  скачанный с зеркала, совпал по хешу с тем, что Docker Hub пытался отдать напрямую.
- Образы из `nvcr.io` и то, чего нет в `mirror.gcr.io`, CI копирует в реестр проекта на GitHub
  (GHCR): у раннеров GitHub доступ к обоим реестрам есть. Узел получает их через тот же
  `registries.yaml`. Это делается на этапе 3, когда понадобится device plugin.

Доверяем только двум источникам: зеркалу Google и собственному реестру. Хеши слоёв защищают
от порчи по дороге, но не от подмены, потому что манифест с этими хешами выдаёт то же зеркало.

## Последствия

- Манифесты переносимы: на машине без `registries.yaml` те же образы скачаются из исходных реестров.
- Установка узла становится на два файла и один архив длиннее, зато всё лежит в репозитории,
  а не в истории терминала.
- Архив образов k3s привязан к версии, поэтому версия k3s в инструкции зафиксирована. При
  обновлении архив скачивается заново.
- `mirror.gcr.io` хранит только популярные образы. Если нужного там нет, containerd пойдёт
  на Docker Hub и упадёт так же, как без зеркала. Такой образ добавляется в копирование через CI.
- До этапа 3 видеокарта не является ресурсом кластера: поды получают её через
  `runtimeClassName: nvidia`, без `nvidia.com/gpu` в `resources`.

## Отвергнутые варианты

- **VPN.** На Windows 10 ломает сеть в WSL.
- **Заменить адреса образов в манифестах.** Работает, но зашивает сетевые особенности одной
  машины в код проекта.
- **Публичные «зеркала Docker Hub».** Их много, но любое из них может подменить содержимое образа.
- **Собирать образы локально.** Нужен Docker и время на каждую сборку, а для чужих образов вроде
  vLLM и Ollama это переупаковка без пользы.
