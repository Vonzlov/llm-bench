# LLM Bench

Сервис выбора LLM под задачу. Загружаешь набор примеров, отмечаешь модели — локальные в Ollama
и vLLM или облачные по API — и получаешь сравнение качества, скорости и цены с рекомендацией.
Всё работает на одной машине с GPU в Kubernetes, но архитектура к этой машине не привязана:
новые узлы добавляются без изменений кода.

**Статус:** идёт этап 1, ядро: готовы измерительный клиент, генератор нагрузки, открытые
наборы данных и оценка качества на классификации и извлечении. Этап 0 — каркас, CI, фейковая
модель и k3s, в котором поды видят GPU, — завершён.

## Что уже есть

- `apps/fake-llm` — фейковая модель: OpenAI-совместимый сервер без нейросети, по которому
  проверяется весь стенд.
- `packages/core` — ядро. Измерительный клиент отправляет потоковый запрос в
  OpenAI-совместимый API и замеряет время до первого токена, интервалы между токенами и
  полное время ответа. Генератор нагрузки держит на сервере N запросов одновременно, идёт
  ступенями 1–32 с прогревом и окном замера и считает медиану и 95-й перцентиль задержек,
  токены и запросы в секунду. Тесты сверяют всё это с тем, что задано фейковой модели.
  Команда `bench-datasets` скачивает открытые наборы MASSIVE и XQuAD и собирает из них
  задачи для оценки качества и пул промптов для нагрузки, а `bench-quality` прогоняет модель
  по набору и считает метрики с бутстреп-интервалами.
- CI на GitHub Actions: ruff, mypy, pytest, gitleaks и сборка образа.
- k3s на одной машине: поды получают видеокарту через рантайм NVIDIA. Настройки узла лежат
  в `deploy/node`, порядок установки — в [инструкции](docs/setup-k3s-gpu.md), проверка —
  smoke-тест `deploy/smoke/gpu-smoke.yaml`.
- [Архитектурные решения](docs/adr/README.md) и черновик [каталога моделей](catalog.yaml).

## Быстрый старт

Нужны [uv](https://docs.astral.sh/uv/) и make.

```bash
make install   # зависимости в .venv
make check     # линтеры, типы и тесты — то же, что в CI
make fake-llm  # фейковая модель на http://localhost:8000
make probe     # во втором терминале: один запрос к ней с замерами
make load      # там же: ступенчатая нагрузка, около минуты
make datasets  # открытые наборы в data/, скачивает около 42 МБ
```

Чтобы увидеть очередь, как у Ollama с одним слотом, запусти фейковую модель так:
`FAKE_LLM_MAX_CONCURRENCY=1 make fake-llm` — и снова `make load`.

Проба работает с любым OpenAI-совместимым сервером, например с Ollama:
`uv run bench-probe --base-url http://localhost:11434/v1 --model qwen2.5:0.5b`.

Нагрузка по методике идёт на промптах из XQuAD — их собирает `make datasets`:
`uv run bench-load --prompts data/xquad-ru-load.jsonl`.

```bash
curl http://localhost:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model": "fake-llm", "messages": [{"role": "user", "content": "Привет"}], "max_tokens": 5}'
```

## Наборы данных

`make datasets` скачивает два открытых набора с первоисточников, сверяет их по SHA-256 и
собирает четыре файла в `data/`. Сами данные в репозиторий не попадают: в `datasets/`
лежат только id выбранных примеров, поэтому у всех получаются одни и те же наборы.

| Набор | Задача | Примеров | Источник |
| --- | --- | --- | --- |
| `massive-ru-intent` | Классификация: один интент из 60 | 300 | MASSIVE 1.1, ru-RU, test |
| `massive-ru-slots` | Извлечение слотов в JSON на тех же фразах | 300 | MASSIVE 1.1, ru-RU, test |
| `xquad-ru-qa` | Ответ на вопрос по абзацу | 300 | XQuAD, ru |
| `xquad-ru-load` | Промпты для нагрузки: два абзаца и вопрос | 240 | XQuAD, ru |

Каждая строка набора — JSON с полями `id`, `input` и `expected`; в том же формате будут
загружаться свои наборы. Выборка простая случайная с фиксированным seed, а
`data/manifest.json` хранит версию каждого набора — SHA-256 его файла. Для наборов MASSIVE
там же лежат три примера с ответами из раздела train, которые модель видит перед вопросом:
фраза без слотов, с одним слотом и с двумя, все с разными интентами. Они тоже выбраны
случайно с тем же seed, их id закреплены в `datasets/massive-ru-examples.ids`.

[MASSIVE](https://github.com/alexa/massive) создан Amazon и распространяется по лицензии
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/), [XQuAD](https://github.com/google-deepmind/xquad)
создан DeepMind и распространяется по лицензии
[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/). Мы берём из них выборку и
меняем формат, а тексты оставляем как есть — убираем только невидимый символ BOM в XQuAD.

## Оценка качества

`bench-quality` задаёт модели вопросы из набора и считает метрики. Готовы классификация и
извлечение в JSON, ответы по тексту — следующие. Какая это задача, команда узнаёт по набору.

```bash
uv run bench-quality --dataset data/massive-ru-intent.jsonl --model llama3.2:3b
uv run bench-quality --dataset data/massive-ru-slots.jsonl --model llama3.2:3b --constrained
uv run bench-quality --dataset data/massive-ru-intent.jsonl --model llama3.2:3b --shots 0
```

Адрес сервера задаётся опцией `--base-url`, как у `bench-probe`. Запросы идут с температурой 0
и фиксированным seed, временные сбои повторяются до трёх раз; что не помогло, засчитывается
как неверный ответ.

**Примеры с ответами.** Перед каждым вопросом модель видит три примера из раздела train,
одни и те же для всех моделей. Они подаются как прошлые реплики диалога: вопрос пользователя
и ответ ассистента ровно в том формате, который принимает разбор. Без примеров модель угадывает
не только ответ, но и правила разметки — что в MASSIVE значение слота «кухне», а не «на
кухне», а пустой ответ — `{"slots": []}`; примеры показывают это напрямую. `--shots 0`
спрашивает без примеров. Если примеров в наборе меньше, чем просили, команда останавливается:
скорее всего, наборы собраны старой версией, и их нужно пересобрать через `make datasets`.

**Классификация.** Модель получает список категорий и текст и должна ответить только названием
категории. Ответ разбирается строго: если после снятия кавычек, точки и регистра его нет в
списке, он неверный и вдобавок попадает в долю ответов «вне списка». Так видно отдельно, где
модель не знает ответ, а где не следует формату.

**Извлечение.** Модель возвращает JSON `{"slots": [{"type": …, "value": …}]}`, где значение —
дословный фрагмент текста без предлогов и соседних слов: так размечен эталон MASSIVE. В
свободном режиме ответ разбираем сами и прощаем только обёртку в блок кода Markdown. С
`--constrained` движок получает JSON-схему — тип из списка, непустое значение, не больше 10
слотов — и не даёт модели выйти за неё. Два прогона рядом показывают, сколько валидности
даёт схема и сколько она стоит в скорости. Значения сравниваются без регистра, лишних пробелов
и знаков препинания по краям, е и ё не различаются.

| Метрика | Задача | Что значит |
| --- | --- | --- |
| Точность | Классификация | Доля верных ответов |
| macro-F1 | Классификация | Среднее F1 по классам: редкие весят столько же, сколько частые |
| Вне списка | Классификация | Доля ответов, которых нет среди вариантов |
| Валидный JSON | Извлечение | Доля ответов, которые разбираются как JSON |
| По схеме | Извлечение | Доля ответов, которые ещё и подходят под схему |
| F1 по слотам | Извлечение | micro-F1 по парам «тип — значение» на всём наборе |

У каждой метрики — 95-процентный бутстреп-интервал по 1 000 повторным выборкам: на 300
примерах точность гуляет примерно на ±5 процентных пунктов, и интервал это показывает.
Если модель упёрлась в лимит токенов, итог говорит, сколько ответов обрезано. Ответ на каждый
пример пишется в `data/results/<набор>--<модель>.jsonl` — со схемой к имени добавляется
`--schema`, без примеров `--0shot`, — итог прогона лежит рядом, в `.summary.json`.

## Фейковая модель

Это эталонная гиря для стенда. Модель отвечает по тому же API, что vLLM, но нейросети внутри
нет: время ответа, очередь и сбои задаются настройками. Если генератор нагрузки показывает на ней
200 мс до первого токена и 200 мс заданы, линейка верна. Если нет — ошибка в нашем коде, а не в модели.

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `FAKE_LLM_SERVED_MODEL_NAME` | `fake-llm` | Имя модели; запросы к другому имени получают 404, как у vLLM |
| `FAKE_LLM_TTFT_MS` | `200` | Время до первого токена, мс |
| `FAKE_LLM_TOKENS_PER_SECOND` | `50` | Скорость генерации после первого токена |
| `FAKE_LLM_OUTPUT_TOKENS` | `64` | Длина ответа, если клиент не задал `max_tokens` |
| `FAKE_LLM_MAX_CONCURRENCY` | `0` | Сколько запросов обрабатывается одновременно, остальные ждут в очереди; `0` — без ограничения |
| `FAKE_LLM_ERROR_RATE` | `0` | Доля ответов 500 |
| `FAKE_LLM_RATE_LIMIT_RATE` | `0` | Доля ответов 429 с заголовком `Retry-After` |
| `FAKE_LLM_TRUNCATE_RATE` | `0` | Доля стримов, оборванных на середине |
| `FAKE_LLM_SEED` | — | Зерно случайных чисел, чтобы сбои повторялись от запуска к запуску |

Тесты в `tests/unit/fake_llm` поднимают настоящий сервер и проверяют по HTTP, что время до
первого токена, скорость и очередь совпадают с заданными.

## Куда движется проект

| Этап | Что появится |
| --- | --- |
| 0. Фундамент | Каркас, CI, фейковая модель, k3s с GPU, каталог моделей |
| 1. Ядро | Адаптеры к Ollama, vLLM и облачным API, метрики качества, генератор нагрузки, бутстреп |
| 2. API и интерфейс | FastAPI и Streamlit: наборы, запуск, сравнение, рекомендация |
| 3. Kubernetes и serving | Планировщик, Job'ы, vLLM и Ollama в кластере, GPU как ресурс кластера, e2e на k3d и kind |
| 4. Эталонный прогон | Сравнение моделей и движков, отчёты в `reports/` |
| 5. Наблюдаемость | Prometheus, Grafana и итоговый README |

## Что сознательно не делаем

RAG и эмбеддинги, дообучение, tool calling, авторизацию и многопользовательский режим, облачный
деплой и настоящий многоузловой кластер. Архитектура готова к нескольким узлам — с этапа 3 это
проверяет e2e в CI, — но разворачивать их проект не будет.
